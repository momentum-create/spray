# P0（セキュリティ・インフラ）実行プレイブック

**対象サイト:** www.spray166.com  
**所要目安:** 2〜4 週間（ホスティング対応速度に依存）  
**前提:** テーマ刷新（P1）の**前**に本番へ入れてよい作業群

---

## P0 とは何か（ひとことで）

> **「サイトを安全に HTTPS で開ける状態にし、WordPress とサーバーの老朽化リスクを下げる」** フェーズです。

デザイン変更や `/skatepark/` への URL 変更は **P0 ではやりません**。  
見た目はほぼそのままで、**裏側の土台**だけ直します。

### P0 で直すこと / 直さないこと

| P0 でやる | P0 ではやらない（P1 以降） |
|-----------|---------------------------|
| SSL 証明書の修復 | 新デザイン・BeTheme 廃止 |
| HTTP → HTTPS 強制 | `/aircraft/` → `/skatepark/` 等の URL 変更 |
| WordPress・PHP の更新 | ニュース CPT・トップ再設計 |
| 管理画面の守り（WAF・2FA） | alt 文言の一括修正 |
| 問い合わせフォームの HTTPS 化 | Google Maps 埋め込み |

### なぜ最優先か

1. **問い合わせフォーム**で名前・メールを送っている → HTTP は盗聴リスク  
2. Chrome が **「保護されていない通信」** と表示 → 離脱  
3. Google は HTTPS を評価シグナルに使用  
4. 現状は証明書検証エラーの可能性あり → **HTTPS 強制の前に証明書修復が必須**

## 全体の流れ（何から手を付けるか）

```
[準備] バックアップ・担当割り当て
    ↓
[サーバー] SSL 証明書を正す（ここが最初の本丸）
    ↓
[検証] ステージング or 深夜に HTTPS がエラーなく開けるか確認
    ↓
[サーバー] PHP 更新・OpenSSL 更新（ホスティング作業）
    ↓
[WP] ステージングでコア・プラグイン更新 → 表示確認
    ↓
[WP] 本番：サイト URL を HTTPS に + DB 内 http→https 置換
    ↓
[サーバー] HTTP→HTTPS 301 + HSTS
    ↓
[WP] セキュリティ強化（WAF・ログイン・2FA）
    ↓
[WP] メニュー・固定ページの EC リンクを https に
    ↓
[検証] フォーム送信・SSL Labs・スマホ実機
    ↓
P0 完了 → P1（デザイン・URL 再編）へ
```

**絶対に順番を入れ替えないこと**

| やってはいけない順序 | 起きる事故 |
|---------------------|------------|
| 証明書修復前に HTTPS 301 を ON | 全ページがブラウザ警告で開けない |
| バックアップ前に DB 置換 | 復旧不能 |
| 本番でいきなり PHP 8 + WP 最新 + テーマ古いまま | 真っ白画面（WSOD） |
| プラグイン一括更新後に表示確認しない | トップのスライダー崩壊 |

## Week 1：SSL とサーバー（インフラ担当メイン）

### Step 1 — SSL 証明書の修復 【最初にやる作業】

**目的:** `https://www.spray166.com/` をブラウザで警告なく開ける。

**現状の問題（診断時）**

- HTTP は表示できる
- HTTPS は **証明書検証エラー** の可能性（チェーン不備・期限切れ・ホスト名不一致など）

**作業内容（ホスティング側）**

1. サーバーパネルで SSL 状態を確認  
   - Let's Encrypt なら「再発行」「更新」  
   - 商用証明書なら中間証明書（チェーン）のインストール確認

2. ホスト名の統一を決める（どちらか一方に寄せる）  
   - 推奨: **`https://www.spray166.com/`** を正とする  
   - `https://spray166.com/`（www なし）も使うなら、片方からもう片方へ 301

3. 確認コマンド（開発者向け）  
   ```bash
   curl -I https://www.spray166.com/
   ```  
   → `HTTP/2 200` または `HTTP/1.1 200`、**SSL エラーなし**

4. ブラウザ確認  
   - Chrome シークレットウィンドウでトップを開く  
   - 鍵マーク → 「接続は安全です」

**完了条件（ゲート 1）**

- [ ] Chrome / Safari / スマホで HTTPS 警告なし
- [ ] 証明書の有効期限が **30 日以上**先

**注意:** BeTheme + RevSlider は古い PHP 前提のコードを含むことがある。

**作業（ホスティング）**

**完了条件（ゲート 2）**

### Step 5 — WordPress の「サイトアドレス」を HTTPS に 【要メンテ窓】

**目的:** WordPress が生成する URL（CSS・画像・リンク）を HTTPS ベースにする。

**手順（本番 or ステージングで練習後、本番）**

1. **必ずバックアップ直前取得**

2. `wp-config.php` に一時追加（ループ防止の定番）  
   ```php
   define('WP_HOME', 'https://www.spray166.com');
   define('WP_SITEURL', 'https://www.spray166.com');
   ```  
   ※ 既存の `WP_HOME` / `WP_SITEURL` があれば上書き・統一

3. 管理画面 `設定 → 一般` も  
   - WordPress アドレス: `https://www.spray166.com`  
   - サイトアドレス: `https://www.spray166.com`

4. **データベース内の http 置換**  
   - プラグイン: **Better Search Replace**（ステージングでテスト推奨）  
   - 検索: `http://www.spray166.com`  
   - 置換: `https://www.spray166.com`  
   - 「ドライラン」で件数確認 → 問題なければ実行  
   - `http://spray166.com`（www なし）も同様に処理

5. 表示確認  
   - ページソースで `src="http://` が残っていないか（一部残る場合は Step 7）

**よくあるトラブル**

| 症状 | 対処 |
|------|------|
| 管理画面にログインできない | `wp-config.php` の URL 定義を確認、DB の `siteurl` / `home` を phpMyAdmin で修正 |
| CSS が当たらない | DB 置換漏れ、または `wp-content` 内の http 残存 |
| リダイレクトループ | `WP_HOME` とサーバー 301 の二重設定を見直す |

**完了条件（ゲート 4）**

- [ ] 管理画面・フロントが `https://` で表示
- [ ] 主要ページのソースに http の自ドメイン URL がほぼ無い

---

### Step 6 — HTTP → HTTPS 301 リダイレクト + HSTS 【サーバー設定】

**目的:** ブックマーク・Google インデックスの HTTP アクセスを HTTPS へ寄せる。

**Apache（.htaccess 例）**

```apache
RewriteEngine On
RewriteCond %{HTTPS} off
RewriteRule ^ https://www.spray166.com%{REQUEST_URI} [L,R=301]
```

**nginx（サーバーブロック例）**

```nginx
return 301 https://www.spray166.com$request_uri;
```

**HSTS（SSL が完全に安定してから。最初の 1 週間は様子見でも可）**

```apache
Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
```

**確認**

```bash
curl -I http://www.spray166.com/
# → Location: https://www.spray166.com/ ...
```

**完了条件（ゲート 5）**

- [ ] `http://` でアクセスすると `https://` に 1 回で飛ぶ
- [ ] リダイレクトチェーンが長すぎない（3 回以内）

## 障害時の戻し方（ロールバック）

| 失敗箇所 | 戻し方 |
